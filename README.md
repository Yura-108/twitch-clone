# Twitch Clone

Full-stack pet project — a Twitch-like streaming platform. Monorepo managed with Yarn workspaces.

## Stack

| Layer     | Tech                                                                       |
| --------- | -------------------------------------------------------------------------- |
| Backend   | NestJS 11, GraphQL (code-first, Apollo Server 5), Prisma 7, PostgreSQL, Redis |
| Frontend  | Next.js 16 (App Router), React 19, Tailwind CSS v4                          |
| Auth      | Session-based (`express-session` + Redis store), argon2 password hashing     |
| Tooling   | TypeScript, ESLint 9 (flat config), Prettier, Docker Compose                 |

## Structure

```
twitch/
├── apps/
│   ├── backend/          NestJS API — GraphQL at /graphql
│   │   ├── src/
│   │   │   ├── core/     infrastructure: config, prisma, redis, graphql
│   │   │   ├── modules/  feature modules (auth/account, auth/session)
│   │   │   └── shared/   decorators, guards, types, utils
│   │   ├── prisma/       schema + migrations
│   │   └── media/        seed images (categories, streams)
│   └── frontend/         Next.js web client
├── packages/             shared workspace packages (empty for now)
├── docker-compose.yml    Postgres + Redis
└── .env                  single source of truth for both apps (not committed)
```

Environment variables live in **one** `.env` at the repo root. The backend reads it via
`../../.env` (scripts run with cwd = `apps/backend`); the frontend gets it through
`dotenv-cli` in its own scripts, since Next.js does not look outside its project folder.

## Requirements

- Node.js >= 22
- Yarn 1.x (classic)
- Docker + Docker Compose

## Getting started

```bash
yarn install                 # one lockfile at the root, hoisted node_modules
cp .env.example .env         # then edit the secrets
yarn docker:up               # start Postgres + Redis
yarn db:migrate              # apply Prisma migrations
yarn dev                     # start both apps in one terminal
```

## Ports

| Service        | URL / Port                       |
| -------------- | -------------------------------- |
| Frontend       | http://localhost:3000            |
| Backend        | http://localhost:4000            |
| GraphQL        | http://localhost:4000/graphql    |
| PostgreSQL     | `localhost:5433` (`POSTGRES_PORT`) |
| Redis          | `localhost:6379`                 |

Postgres is mapped off the default 5432 so it does not clash with a locally
installed instance. The mapping and `POSTGRES_URI` both derive from `POSTGRES_PORT`.

## Scripts

All commands run from the repo root.

| Command             | What it does                                        |
| ------------------- | --------------------------------------------------- |
| `yarn dev`          | Backend (watch) + frontend concurrently              |
| `yarn dev:api`      | Backend only                                        |
| `yarn dev:web`      | Frontend only                                       |
| `yarn build`        | Build both apps                                     |
| `yarn lint`         | ESLint across both workspaces                        |
| `yarn format`       | Prettier write across both workspaces                |
| `yarn db:generate`  | Regenerate the Prisma client                         |
| `yarn db:migrate`   | Create + apply a migration (dev)                     |
| `yarn db:push`      | Push the schema without a migration                  |
| `yarn db:studio`    | Open Prisma Studio                                   |
| `yarn docker:up`    | Start Postgres + Redis                               |
| `yarn docker:down`  | Stop them                                            |
| `yarn docker:reset` | Stop, wipe volumes, start fresh                      |

To run a script in a single workspace: `yarn workspace @twitch/backend <script>`.

## Notes

- `apps/backend/src/core/graphql/schema.gql` is generated by Nest but **is committed** —
  it is the API contract, and keeping it in git lets the frontend run GraphQL codegen
  without booting the backend or a database.
- `apps/backend/media/` holds committed seed images. Runtime user uploads belong in
  `apps/backend/uploads/`, which is gitignored.
- ESLint configs stay per-app on purpose: the backend uses `typescript-eslint`
  type-checked rules, the frontend uses `eslint-config-next`. Flat configs do not
  inherit up the tree. Prettier, by contrast, is shared from the root.
